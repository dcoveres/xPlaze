# xPlaze

Экспериментальная библиотека гибридного шифрования на эллиптической кривой **secp256k1**.

Текущая версия: **5**

> ⚠️ Код предназначен только для учебных/исследовательских целей. Не используйте его для защиты реальных данных без независимого аудита.

## Возможности

- ECDH на кривой `secp256k1`
- Эфемерная пара ключей для каждого сообщения
- Вывод ключей через HKDF-SHA256
- Аутентификация сообщения через HMAC-SHA256
- Потоковое XOR-шифрование на основе HMAC-SHA256
- Простой интерактивный CLI в `tests.py`

## Требования

- Python 3.8+
- Библиотека `cryptography`

Установка зависимости:

```bash
pip install cryptography
```

Файлы

· xPlaze.py — основная библиотека: encrypt, decrypt, вспомогательные функции.
· tests.py — интерактивный CLI для генерации ключа, шифрования и дешифрования.

Быстрый старт через CLI

Запустите:

```bash
python tests.py
```

В меню доступны действия:

1. Сгенерировать новый приватный ключ
2. Установить приватный ключ вручную
3. Показать текущий приватный ключ
4. Зашифровать сообщение
5. Расшифровать blob из hex
6. Выход

Пример:

```text
=== xPlaze Шифрование/Дешифрование ===
1. Сгенерировать новый приватный ключ
2. Установить приватный ключ
3. Показать текущий приватный ключ
4. Зашифровать сообщение
5. Расшифровать blob (hex)
6. Выход
```

Использование как библиотеки

```python
import secrets
from xPlaze import encrypt, decrypt, N

# Генерация приватного ключа в допустимом диапазоне
private_key = secrets.randbelow(N - 1) + 1

message = b"Hello, xPlaze!"
blob = encrypt(message, private_key)

print("Blob (hex):")
print(blob.hex())

plaintext = decrypt(blob, private_key)
print("Расшифровано:")
print(plaintext.decode("utf-8"))
```

API

encrypt(msg: bytes, private_key: int) -> bytes

Шифрует сообщение msg с использованием приватного ключа получателя private_key.

· private_key должен удовлетворять условию 1 < private_key < N
· msg не должен быть пустым
· Возвращает бинарный blob

decrypt(blob: bytes, private_key: int) -> bytes

Расшифровывает blob, созданный функцией encrypt.

· private_key должен удовлетворять условию 1 < private_key < N
· При неверном HMAC выбрасывает ValueError("HMAC не совпадает")
· Возвращает исходные байты сообщения

Формат blob

Зашифрованный blob имеет следующую структуру:

```text
[32 байта] iv.x
[32 байта] iv.y
[16 байт]  nonce
[...]      ciphertext
[32 байта] HMAC-SHA256
```

Где iv.x и iv.y — координаты эфемерного публичного ключа отправителя.

Алгоритм

1. Генерируется эфемерная пара ключей k.
2. Вычисляется общий секрет: shared = private_key * ephemeral_public.
3. Из общего секрета и соли выводится пара ключей:
   · ключ шифрования
   · ключ HMAC
4. Сообщение шифруется XOR-потоком, сгенерированным на HMAC-SHA256.
5. Вычисляется HMAC-SHA256 по заголовку, nonce и ciphertext.
6. Результат упаковывается в blob.

Безопасность

Код является экспериментальным и имеет следующие особенности:

· Не проходил независимый аудит.
· Использует самодельную схему потокового шифрования.
· Не обеспечивает аутентификацию отправителя: любой, кто знает публичный ключ получателя, может создать корректный blob.
· Не обеспечивает forward secrecy при компрометации долговременного приватного ключа получателя.
· Не рекомендуется для защиты реальных данных.

Для production-задач лучше использовать проверенные решения:

· cryptography.fernet
· age
· libsodium
· GPG
· TLS/Noise Protocol

Версии

· Версии ниже 4 не рекомендуются.
